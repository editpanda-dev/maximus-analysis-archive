# 막시무스 데이터 처리와 피처 정비 피드백

작성일 2026년 10월 1일  
작업 기한 2026년 10월 4일  
목적 다음 주 모델 학습에 사용할 입력 데이터와 추천 기준을 이번 주 안에 동결한다

## 이번 주 결론

이번 주에는 추천 결과를 더 많이 만드는 것보다 후보군, 목적 분류, 점수 계산, 결측 상태를 하나의 규칙으로 통일한다. 최종 산출물은 `area_code`를 키로 사용하는 786개 공식 상권 피처마트와 재현 가능한 QA 보고서다. 잔차 방식과 가중합 방식을 동시에 최종 점수로 사용하지 않는다.

## 피드백과 반영 방향

### 후보군 26개와 786개 차이

이전의 26개는 공식 상권 코드 결합 및 공간 집계 과정의 불일치로 과소 집계된 값이다. 상권 코드를 7자리 문자열로 표준화하고, 공식 상권 경계에서 400m 범위 안의 도달 정류장을 다시 집계한 결과 25% 기준 후보는 786개로 정정됐다.

발표와 문서에는 단순 정정만 적지 않고 후보 축소 과정을 수치로 제시한다. 서울 전체 공식 상권 수를 분모로 두고 접근률 기준 0%, 25%, 50%, 80%에서 남는 상권 수와 비율을 같은 표로 산출한다. 25% 기준이 실제로 후보를 얼마나 거르는지 이 표로 설명한다.

### 관광특구 처리

관광특구 6개를 데이터에서 삭제하지 않는다. 모든 행을 유지하고 추천 정책만 세 시나리오로 분리한다.

1. 관광특구 포함
2. 관광특구 전체 제외
3. 관광특구 자체 폴리곤은 제외하되 내부의 골목상권, 발달상권, 전통시장 후보는 유지

각 시나리오에서 목적별 Top10과 식사 쇼핑 결합 Top10을 다시 계산하고, Top10 유지 개수, 순위상관, 신규 진입 및 이탈 상권을 비교한다. 기본 정책은 세 번째 시나리오로 검토하되 결과를 본 뒤 확정한다.

### 목적 하위분류의 공통 기준

식사와 쇼핑에만 하위분류가 있고 카페, 공부, 여가문화에는 같은 기준이 적용되지 않았다는 피드백을 반영한다. 다섯 목적 모두 아래 조건 가운데 하나 이상을 충족하면 하위분류를 만든다.

- 이용 행동과 체류 방식이 다르다
- 주요 방문 시간대가 다르다
- 공급 시설 유형이 다르다
- 객단가나 소비 패턴이 다르다

담당 영역은 기존 분담을 유지한다.

| 담당 | 대분류 | 이번 주 필수 산출 |
|---|---|---|
| 김건우 | 식사 쇼핑 | 식사 M1부터 M6, 쇼핑 SH1부터 SH5 정의와 업종 코드 매핑. SH5는 쇼핑 대분류 점수에서 제외 여부를 명시 |
| 장한별 | 카페 공부 | 카페 이용형태와 학습 체류형 하위분류, 시설 포함 제외 기준, 중복 업종 처리표 |
| 지우진 | 여가문화 | 전시 박물관, 공연 영화, 공원 체육, 야간주점 등 하위분류와 시간대 신호 정의 |

업종 하나는 기본 점수에서 하나의 주 목적에만 귀속한다. 제과와 디저트는 카페, 호프와 요리주점은 여가문화로 귀속하고 다른 목적에는 설명용 태그만 남긴다.

### 점수 계산 흐름 통일

이번 주 공식 기준선은 다음 흐름으로 통일한다.

```text
상권 내부 밀도 40%
+ 400m 도보권 밀도 30%
+ 서울 평균 대비 특화도 30%
= 공급점수 U

점포당 매출의 목적별 백분위
= 소비점수 V

Purpose Score = 0.7 × U + 0.3 × V
```

매출 공개율이 30% 미만이면 소비점수를 중립값으로 채우지 않고 공급점수만 제공한다. 이때 `sales_status=missing`을 함께 표시해 관측 매출이 있는 상권과 같은 신뢰도로 해석하지 않도록 한다.

기존 PATH v0의 잔차 점수는 비교용 기준선으로만 보존한다. 발표에서는 원점수, 크기 보정 잔차, Purpose Score를 하나의 최종 점수처럼 섞어 표현하지 않는다. 현재 공식본은 밀도와 특화도로 규모 효과를 직접 줄인 Purpose Score v2다.

### 매출 공개 상태 정정

매출 공개 상태는 목적 점포 업종 중 매출이 공개된 업종의 비율로 결정한다.

| 공개율 | 상태 | 순위 처리 |
|---|---|---|
| 70% 이상 | observed | 공급과 소비를 모두 반영 |
| 30% 이상 70% 미만 | estimated | 공급과 소비를 반영하되 추정 상태 표시 |
| 30% 미만 | missing | 공급점수만 사용하고 별도 상태로 정렬 |

따라서 매출 공개율이 24%인 상권에 점포와 매출이 모두 관측됐다는 문구를 표시하면 안 된다. 기존 설명 카드와 발표 예시에서 이 모순을 전부 제거한다.

### 가중치 민감도

현재 가중치는 학습된 최적값이 아니라 기준선이다. 공급과 소비 비중을 50대50, 70대30, 80대20으로 바꾸고 접근성 가중치를 0%, 10%, 20%로 바꿔 목적별 Top10을 다시 계산한다.

각 조합에 대해 기본안 대비 Top10 유지 개수와 Spearman 순위상관을 출력한다. 특정 상권이 여러 조합에서 계속 상위권이면 안정 후보, 가중치에 따라 크게 움직이면 탐색 후보로 표시한다.

### 추천 근거 문장

데이터 필드는 내부 상세 정보로 보존하되 사용자의 기본 화면에는 자연어 근거를 표시한다.

- `minimum_period_ratio=0.99` → 아침 오후 저녁 모두 동대문구 대부분의 출발지에서 30분 안에 도착할 수 있어요
- `sales_status=observed` → 관련 업종의 매출과 점포 구성이 충분히 관측됐어요
- `sales_status=estimated` → 점포 구성과 일부 공개 매출을 함께 반영했어요
- `sales_status=missing` → 매출 공개가 부족해 점포와 시설 구성을 중심으로 추천했어요

숫자는 상세 보기에서만 제공하고 기본 카드에는 사용자 문장을 우선한다.

## 이번 주 즉시 실행할 액션 아이템

### 우선순위 1 후보군과 공간 기준 확정

- [ ] 서울 전체 공식 상권 수와 접근률 0%, 25%, 50%, 80%별 후보 수를 산출한다
- [ ] 26개가 과소 집계된 원인과 786개 정정 과정을 한 문단으로 기록한다
- [ ] 모든 `area_code`를 7자리 문자열로 통일한다
- [ ] 400m 집계가 직선거리인지 보행거리인지 컬럼과 문서에 명시한다
- [ ] 관광특구 포함, 제외, 내부 세부상권 유지 시나리오별 Top10 변화를 산출한다

완료 기준은 후보군 표, 관광특구 민감도 표, 786개 고유키 검사가 모두 존재하고 같은 입력에서 재현되는 것이다.

### 우선순위 2 목적 분류표 확정

- [ ] 다섯 목적별 하위분류 코드, 포함 시설, 제외 시설, 주요 시간대, 소비 신호를 한 표로 통합한다
- [ ] 제과 디저트, 호프 요리주점, 서점 문구처럼 경계가 겹치는 업종의 최종 귀속을 확정한다
- [ ] 한 업종이 둘 이상의 목적 기본 점수에 중복 산입되지 않는지 검사한다
- [ ] 하위분류가 만들어진 근거를 이용 행동, 시간대, 시설, 소비 패턴 중 하나 이상으로 기록한다

완료 기준은 taxonomy 표와 자동 중복 검사 결과 0건이다.

### 우선순위 3 피처마트와 점수식 동결

- [ ] 786개 상권에 대해 접근성, 내부 공급, 400m 도보권 공급, 특화도, 매출 상태, 소비 피처를 결합한다
- [ ] Purpose Score v2를 공식 점수로 고정하고 PATH v0 잔차는 비교 컬럼으로만 남긴다
- [ ] `observed`, `estimated`, `missing`별 행 수를 목적별로 출력한다
- [ ] 관광특구, 도매 검토, 넓은 상권, 소규모 상권 플래그를 유지한다
- [ ] 공급 소비 가중치와 접근성 가중치 민감도를 계산한다

완료 기준은 `area_code` 중복 0건, 목적별 점수 0에서 100 범위, 가중치 합 1, 결측 상태 누락 0건이다.

### 우선순위 4 설명 카드와 발표 정정

- [ ] 내부 수치를 사용자 문장으로 바꾸는 템플릿을 목적별로 만든다
- [ ] 매출 공개율 24%와 완전 관측 문구가 동시에 표시되는 기존 사례를 수정한다
- [ ] 점수 계산 흐름을 공급점수, 소비점수, 최종 Purpose Score 순으로 한 장에 표현한다
- [ ] 26개를 사용하는 과거 장표와 대본을 786개 및 정정 설명으로 교체한다

완료 기준은 임의의 상권 10개에 대해 설명 카드가 피처 상태와 모순되지 않는 것이다.
