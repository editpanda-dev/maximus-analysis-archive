## 산출물 우선순위와 실행 순서

ZIP의 `project`는 1~7번 인계용 코드·원천 스냅샷·중간 결과·최신 결과·테스트·버전 고정 파일을 포함한다. Git에 없는 식사 점포 원천이나 실제 출입구 증거까지 포함된 것은 아니다. API 키·.env·가상환경과 무관한 로컬 원시 ZIP 변경은 포함하지 않는다.

- `steps1_2_20261006`: 보행 근거 등급, 정확한 분모, 환경 검수.
- `steps3_5_20261006`: 공부 v0, 반경·인접 가중치·규모 보정 진단, 공통 내부 공급 피처. 이 폴더의 카페 공급 전용 순위 232개는 과거 이력이다.
- **`steps6_7_20261006`: 최종 사용 순위·scorecard·설명·지도·정정·QA. 카페 공급 전용 184개 결과를 사용한다.**

위 세 폴더의 공통 상위 경로는 `data/processed/cafe_study_taxonomy/`다. 과거 10/3 통합표의 75% 공부 부분합·208개 조합을 이번 최종안으로 사용하지 않는다.

Windows PowerShell에서 ZIP을 푼 `project` 폴더로 이동한 뒤 실행한다. `.venv-repro`가 이미 있으면 생성·설치 단계는 재사용 가능하다.

```powershell
py -V:3.12 -m venv .venv-repro
.\.venv-repro\Scripts\python.exe -m pip install -r requirements-windows-py312-lock.txt
.\.venv-repro\Scripts\python.exe -m pip check
.\.venv-repro\Scripts\python.exe -m scripts.audit_hanbyeol_steps1_2
.\.venv-repro\Scripts\python.exe -m scripts.build_hanbyeol_steps3_5_20261006
.\.venv-repro\Scripts\python.exe -m scripts.build_hanbyeol_steps6_7_20261006
.\.venv-repro\Scripts\python.exe -m pytest -q tests/test_hanbyeol_walk_access.py tests/test_prepare_hanbyeol_steps_1_3.py tests/test_hanbyeol_oct06_integration.py tests/test_hanbyeol_route_evidence_labels.py tests/test_hanbyeol_steps3_5.py tests/test_hanbyeol_steps6_7.py
```

OSM PBF 전체 재추출과 실시간 API 호출은 위 재현에 필요하지 않다. 이전 통합 스크립트의 BLOCKED_ROUTE/BLOCKED_EVIDENCE/BLOCKED_FINAL_SCORE는 과거 목표에 대한 표시로 보존하며, 현재 S4 제외 v0 제출 범위 및 공통 보행망 미완료 상태와 별도로 해석한다.

최신 전체 회귀·신규 테스트는 Linux Python 3.12.14에서 13개 통과했고, 사용자 Windows Python 3.12.10의 기존 5개 통과·pip check 정상 로그와 구분했다. 합본 생성은 새 경로를 수집하거나 점수 정의를 바꾸는 작업이 아니다. 전달 패키지는 아래 세 배치 실행 및 테스트를 별도로 검수한다.

## 추가 자료가 필요한 남은 범위

- 실제 공통 보행망 통합: 식사 점포 원천 ZIP/좌표·고유 ID·업종 매핑·파일 해시·사용 조건, 공통 경로 캐시 또는 네트워크, 경계 출발점·스냅·셀/점포 단위·미해결 처리 합의.
- 실제 출입구·현재 보행 허용·영업 상태: 동일 기준의 시설별 증거/확인 기록.
- S4를 향후 포함할 경우: 427개 후보에 동일 규칙의 URL·인용·좌석/학습 허용·검토자·검토일 판정표. v0는 이 자료 없이 S4를 제외한다.
- 검증된 세 가지 체류·학습 활동 하위분류: 현재 두 개 공급 신호로는 충족하지 않으므로 세 번째 항목을 임의 생성하지 않는다.
- 공부 규모 보정 방식 채택: 개수 기반 v0와 잔차/밀도 진단 사이의 팀 선택. 현재 v0 면적 상관 0.322를 숨기지 않는다.

## Git 인계

코드·결과 로컬 커밋은 `ab2855a53706ce9963dc36df9662dc606c0b70de`다. 이번 합본 문서도 별도 로컬 커밋으로 보존하며 최종 전달 SHA는 ZIP의 `DELIVERY_RECEIPT.md`에 기록한다. push는 수행하지 않는다.

Git bundle은 기초 커밋 `e089ee81e6ab0216982c32e3bb6941f840bc2fef`가 필요한 증분 이력이다. 저장소 소유자는 기존 저장소에서 `git bundle verify`로 확인하고 `git fetch <bundle경로> HEAD`로 가져온 뒤 검토할 수 있다. 새 전체 저장소 복제본 또는 원격 반영 완료를 뜻하지 않는다. 이전 보고서의 옛 bundle 이름·SHA·push 명령은 실행 이력이며 최신 인계는 이 ZIP의 단일 bundle과 receipt를 사용한다.

### 1. 과거 push 실패 이력과 향후 권한 확인

일반 Git push 실패 이유는 이 실행 환경의 Git HTTPS 인증 부재다. 별도 연결 앱에서는 저장소 push=true 메타데이터가 있었지만 브랜치 생성이 HTTP403 Resource not accessible by integration으로 실패했다. 정확한 원인은 소유자의 설치 권한/조직 정책 확인이 필요하다.

소유자는 GitHub App 설치의 저장소 포함 여부, Contents: Read and write 승인 여부, 연결 계정 write 권한 및 브랜치 정책을 확인한다. 소유자의 인증된 Windows Git으로 직접 bundle을 공유할 수도 있다. 카카오 API 키는 GitHub 쓰기 인증과 관계없으며 추가 제공할 필요 없다.

### S4와 중복 신호 제외

- 팀 결정대로 C_stay/S4는 제외한다. 검토 후보 427개는 여전히 unknown이며 학습 허용을 확인한 장소로 승격하지 않는다.

```text
공부 시설 접근성 v0 = 0.600000 × P(스터디카페 가중 집계)
                     + 0.266667 × P(공개 학습시설 가중 집계)

```

`P`는 786개 상권의 해당 신호에서 **양수 값끼리** 동률 평균 백분위(0~100)를 계산한다. 집계 규칙상 0은 0점으로, 입력 결측은 결측으로 유지한다. 이 방식은 상대적 정렬 규칙이며 만족도 점수가 아니다. 접근성 백분위는 기존 334개 출발지/30분 분석의 입력을 그대로 사용하며 사용자 특정 출발지나 실시간 교통으로 해석하지 않는다.

시설 두 신호가 모두 0이면 총점은 NA이고 순위에서 제외한다. 여기서 0은 ‘이번 원천과 포함 규칙에서 0건’이다. 연결 미확보나 원천 미수집 때문에 실제 시설이 누락됐을 수 있으므로 시설 부재를 확정한 뜻은 아니다. 시설 없이 교통 접근성만으로 공부 상권을 추천하지 않는다.

## 4. 세 목적의 접근성 정의 검토 및 공통 대안

### 실제로 확인한 문제

김건우님 최신 코드에는 `--walk-routes`와 보행망 계산 절차가 추가돼 있다. 하지만 제출된 786행 `walk_distance_basis`와 QA는 **전부 euclidean_400m_buffer**다. 코드가 있다는 사실만으로 이미 보행 결과가 적용됐다고 간주하지 않았다. 코드의 경로 누락 처리에는 직선거리 fallback도 있어, 캐시 적용 후에도 정의 혼합 여부를 점검해야 한다.

카페 초안은 공식 상권 내부 점포·매출을 사용하고 외부 POI 보행 반경을 점수에 더하지 않는다. 공부 v0는 내부+OSM 잠정 외부400m를 사용한다. 따라서 세 기존 점수를 바로 평균해 ‘동일 보행 정의의 최종 조합’으로 발표할 수 없다.

### 수행한 공통 내부 공급 비교안

- 동일 공식 폴리곤의 **내부만** 포함한다. 모든 외부 시설을 제외하며 내부 거리는 집계 규칙상 0m다.

- 공부: 이번 후보쌍의 내부 스터디카페·공개 학습시설만 사용. S4/S3b/외부 연결은 제외.

## 8. 1·2번 Git 원격 공유 실패 원인과 실행 가능한 대안

일반 `git push`는 `could not read Username for https://github.com`으로 실패했다. 현재 실행 환경에 Git HTTPS 쓰기 인증이 없다. 연결 GitHub의 저장소 metadata는 pull/push=true였지만 실제 작업 브랜치 생성 호출은 **HTTP403 Resource not accessible by integration**으로 실패했다. 별도 API를 반복하거나 main을 강제 갱신하지 않았다. 원격 branch 생성과 commit 반영은 완료되지 않았다.

### repository owner가 할 일

- 연결 GitHub App 설치에서 이 저장소가 포함돼 있는지, **Contents: Read and write** 권한이 승인돼 있는지 확인/갱신한다. 메타데이터의 push=true만으로 앱 쓰기가 실제 허용된다고 보장하지 않는다.
- 조직/저장소의 브랜치 생성 정책과 연결 계정의 write 권한도 확인한다. 정확한 403 원인 판별에는 소유자의 설치 권한·정책 확인이 필요하다.
- 권한 갱신 후 작업 브랜치 생성·파일 반영을 다시 확인한다. API 키와 이 GitHub 쓰기 권한은 별개다. 카카오 키를 Git 인증에 사용하지 않는다.

### 사용자 Windows에서 1·2번 커밋을 공유하는 방법

ZIP에 `maximus_steps1_2_1a69e28.bundle`을 넣었다. 이는 커밋 내역을 보존한 Git 전송 파일이며 1·2번까지의 정확한 HEAD는 `1a69e28763f84792eaf4354597751d3849fb4c3e`다. 작업 폴더의 ZIP을 다시 commit하는 방식과 다르다. 아래는 압축을 `C:\work_maximus\maximus_steps3_5_delivery`에 풀었다는 기준이다.

기존 공급 전용 232개 중 48개는 원천 커피·제과점 수가 모두 0인데 잔차 점수가 양수였다. 이를 시설 공급 근거로 순위에 포함하는 오류를 발견했다. 이번 순위에는 원천 공급 합계 > 0 조건을 추가했다. 기존 점수는 `legacy_supply_only_score_before_rank_guard`에 보존하고, 새 공급 전용 순위 점수는 해당 48개를 결측 처리했다. 원천 `score_status` 개수 자체는 변경하지 않았다.

공급 전용 Top10은 수정 전후 9개가 공통으로 유지됐다. 이전 Top10의 번동시장은 원천 0점포여서 제외됐다. 정정 대상 48행과 Top10 전후 비교표를 별도 제공한다. 이전 보고서의 232개는 관측 상태 수이며, 최신 순위 모집단은 184개로 정정된다.

### 지도 원본 폴리곤 자기교차

성수초등학교(3110137), 혜원여고(3110270), 중랑역 4번(3110234), 도봉역 2번(3110407)의 원본 폴리곤 자기교차를 발견했다. 원본을 유지하고 지도용 복사본에만 Shapely `make_valid`를 적용했다. 보정 전후 투영 면적 차이의 절댓값은 최대 약 4.7×10^-10㎡로 검수 허용 기준 0.001㎡보다 작았다. 기존 공간 집계·점수는 재산정하지 않았다. 수정 감사표와 GeoJSON의 표시용 보정 여부 열을 제공한다.

## 4. 점수 정의와 미완료 범위

공부 v0은 S4를 제외한다. S3b 공식 독서실 수는 검증용이며 점수에 더하지 않는다. 기존 45% 스터디카페, 20% 공개 학습시설, 10% 대중교통 접근성을 합계 75%로 재정규화하여 각각 60%, 26.6667%, 13.3333%로 사용한다. 시설 가중집계는 내부 + 0.25×잠정 OSM 400m 외부시설이다. 시설 신호의 0은 0으로 유지하고 양수 관측값 사이의 백분위를 사용한다. 포함 시설 신호가 없는 상권은 점수를 결측 처리한다. 이는 실제 시설 부재 확정이 아니다.

10,132개 보행 후보쌍은 inside_area 813, routed 108, 직선 출입 연결 가정 7,165, 연결 미해결 2,046개다. routed도 실제 출입구 검증 완료를 뜻하지 않는다. 외부시설 보행 접근성은 OSM 보행망과 최대 30m 출입 연결 가정이 섞인 탐색 자료다. 지도·순위 생성으로 이 불확실성이 해결된 것은 아니다.

S4 427개는 학습 허용 근거 미검증이므로 점수 제외 상태를 유지한다. 공개 학습시설 채택 195개에는 운영 상태 unknown인 원천 항목이 포함되며, 현재 운영 확인 완료 시설 수로 설명하지 않는다. 공부 v0은 시설 접근성 탐색 기준선으로 발표한다.

실제 공통 보행망 조합 점수에는 김건우님 식사 점포 좌표 원천과 보행 경로 캐시 등 현재 Git에 없는 입력이 필요하다. 이번 내부 공급 조합은 이 자료를 대체하거나 실제 보행거리 통일을 주장하지 않는다. 추가 입력 없이 수행 가능한 6·7번 범위는 완료했으나, 위 제한은 `remaining_inputs_and_scope.csv`에 남겼다.

## 7. Git 인계 기준

사용자 변경 요청에 따라 로컬 커밋까지 수행하며 원격 push는 이번 완료 조건이 아니다. 신규 코드·테스트·문서·결과를 한 커밋으로 묶는다. 기존 원시 ZIP의 별도 로컬 변경은 이번 작업과 무관하여 포함하지 않는다. 커밋 SHA와 전달 파일 검수 정보는 ZIP의 `DELIVERY_RECEIPT.md`에 기록한다. 저장소 소유자는 전달된 커밋을 검토한 뒤 필요한 브랜치에 반영하면 된다.
