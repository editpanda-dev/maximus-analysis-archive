## 1. 배경 및 핵심 방향성 (Direction)

### [진행 목적]
- 막시무스 기존 산출물: 동대문구 출발 대중교통 30분 안 서울 공식 상권 786곳을 목적별(식사·카페·쇼핑·여가문화·공부)로 점수화
- 한계: 점수가 높은 곳 = 이미 유명한 곳(명동, 종각, 잠실 등) → 사용자에게 새 정보가 없음
- 목표: **"학생이 몰랐지만 실제로 갈 만한 곳"** 추천으로 확장
- 1차 활용처: 2026 AI 캠퍼스 바이브코딩 경진대회(한국외대 캠퍼스 출발, 기획서 마감 11-10)

### [핵심 방향성]
| 원칙 | 내용 | 이유 |
|---|---|---|
| 인기 대신 의외성 | "늘 가던 곳(관성)과 다르지만 갈 만한 곳"을 위로 올림 | 인기순은 사용자가 이미 아는 곳만 반복함 |
| 관련성 하한 | 갈 만하지 않은 곳은 의외여도 제외 | 의외성만 높이면 만족도가 떨어진다는 선행연구 |
| 단위 축소 | 캠퍼스 생활권 → 서울 상권 786곳 → 상권 안 가게 | 상권 단위로는 실제 방문 행동으로 이어지지 않음 |
| 공공데이터 우선 | 인허가·상가정보·착한가격 기반, 리뷰는 보조 신호 | 재현 가능, 공개 저장소에 근거 제시 가능 |
| 성능 주장 보류 | 정답 라벨이 생길 때까지 정확도 주장 안 함 | 개인 방문 이력·만족도 데이터가 없음 → 설문으로 검증 |

### [전체 궤적]
```
Phase 1  글캠 30분 숨은 곳 (10/29~31)
   │  '숨은'을 잴 데이터가 없음 → 정의부터 다시
Phase 2  상권 의외성 모델 SERP v0 (11/2)
   │  설계 근거 논문을 원문으로 확인할 필요
Phase 3  선행연구 검증 → SERP v1 재설계 (11/2~3)
   │  상권 폴리곤이 넓어 어느 가게로 갈지 모름
Phase 4  점포 단위 추천 v0·v1 (11/2~3)
   │  가게 성격(분위기·혼밥·공부)은 공공데이터에 없음 → 네이버 수집 429 차단
Phase 5  리뷰 수집 경로 조사 (11/3)
         크롤링 막힘 → 공식 API 평판·키워드 대안
```

## 2. 논리 흐름 및 전개 과정 (Logical Flow)

### Phase 1: 글로벌캠퍼스(용인 모현) 30분 숨은 곳 탐색
**문서**: `[campus-hidden-spots] docs/campus/` · 기간 10/29~31

**이유/판단**
- 대회 주제(캠퍼스 생활)에 맞춰 동대문 상권 방법을 글캠 출발로 이식
- 검증할 통념: "글캠 주변에는 갈 곳이 없다"
- 당시 원칙: 리뷰 없이 공공데이터만 사용(11/3 팀 확인으로 변경, Phase 5)

**진행 방식**
- **도달 모형 구축**
  - GBIS 노선·정류소로 캠퍼스 출발 버스 시간 추정
  - ODsay 실측 13곳으로 보정 → 평균오차 3.1분
  - 캠퍼스에서 바로 걷기는 직선 1km까지만 인정
- **상권 스코어카드 v0**: 상가정보 점포 군집 94개 중 30분 안 11개, 동대문 규칙(공급 0.7 + 동 단위 카드매출 0.3) 그대로 적용
- **숨은 가게 태그**: 인허가 기준 노포(2005년 이전), 10년+, 개인카페, 희소 업종, 착한가격
- **명소 v0**: 카카오 관광·문화, 도시공원, 공공시설 개방, TourAPI, 공공체육시설 통합
- **추천 목록 v1**: 단계 분리(대중교통 30분 / 45분 확장 / 셔틀 / 차 30분), 행마다 대기 포함 시간 표시

**결과**
| 발견 | 근거 |
|---|---|
| 30분 생활권 = 모현읍 + 오포뿐 | 12km 안 점포 14,645곳 중 1,495곳(10%). 경안동·분당·용인 시내는 38분 이상 |
| 주변 명소 부족 확인 | 30분 안 관광·문화 명소는 캠퍼스 안 2곳 + 모멘토리아트홀뿐. 나머지 36곳은 체육시설·공원 |
| 숨은 가치는 상권 안 가게 | 오포 양벌·매산·문형에 1986~1999년 노포 밀집(들밥, 막끌리네, 캠핑7, 고래성) |
| 오포가 새로 갈 곳 | 오포2동 양벌로: 30분 안 쇼핑 76, 카페 92로 1위, 20.8분 |
| 셔틀은 30분 상권을 못 엶 | 하교편은 판교·서현뿐, 45~50분, 돌아오는 편 없음 |
| 대기시간이 결론을 좌우 | 배차 절반을 대기로 넣으면 30분 안 상권 11 → 6곳, 점포 1,495 → 634곳 |

- 추천 목록 규모: 대중교통 30분 243곳, 차 30분 2,702곳, 셔틀 298곳
- 민감도: 상권 수는 기준값에 따라 6~25곳으로 흔들림, 상위 3곳은 대부분 유지 → **순위는 안정적, 개수는 불안정**
- 서울캠 확장: 인허가 16만 건으로 상권 786곳 태그, 30분 안 274곳(ODsay 측정 60곳 + 직선 4km 추정 214곳)

**한계 (스스로 짚은 것, 심각한 순)**
1. '숨은 곳' 미검증: 노포 = 인허가가 오래됐다는 뜻일 뿐, 학생이 모르는지는 모름
2. 목록이 큼(차 30분만 2,702곳), 정렬이 태그 개수뿐
3. 30분 판정 불확실: 글캠은 대기 미포함, 서울캠은 78%가 직선 추정
4. 목록의 약 90%가 차 30분 단계인데 학생 대부분은 차가 없음
5. ODsay 키 하루 약 30건 한도 → 서울캠 측정 89/773건에서 정체

**다음 단계로 넘어간 판단**
- '숨은'을 노포 같은 대리 지표로 계속 쌓는 건 한계 → **측정 가능한 정의가 필요**
- 인기도·인지도 데이터 없음 → "집단의 관성이 추천하지 않는 곳"으로 재정의
- 캠퍼스 11곳으로는 통계적으로 약함 → 상권 786곳이 있는 동대문 데이터에서 모델부터 만들기로 함

### Phase 2: 상권 단위 의외성 추천 모델 (SERP v0)
**문서**: `[serendipity] docs/serendipity/recommendation_design.md` · 코드 `scripts/build_serendipity_ranking.py` · 11/2

**이유/판단**
- '숨은 곳'을 "관성 기준선이 상위에 올리지 않는 곳"으로 정의 → 데이터로 계산 가능
- 개인 이력이 없음 → "이 사용자에게 의외"가 아니라 "동대문구 출발 집단에게 의외"로 범위 한정
- 교수님 피드백 반영: 복잡 모형 대신 규칙 점수·Ridge·백분위만 사용, 관성 기준선(baseline) 명시

**진행 방식**
- **관성 기준선 3개** (목적별, 상위 10곳 합집합 = 관성 Top-K)

| 기준선 | 정의 |
|---|---|
| 거리순 | 동대문구 상권 중심점에서 가까운 순 |
| 인기순 | 직전 분기 목적 매출 순 |
| 과거 유입순 | 비일상 유입 × 동대문구 30분 도달률(동대문구발 OD가 없어 프록시) |

- **관련성 R** = 백분위(0.8 × 매력도 + 0.2 × 접근성)
  - 매력도: 총 점포 수·면적·업종 엔트로피·목적 점포 비중·상권 유형으로 목적 매출을 예측한 Ridge 교차적합값
  - 실제 매출이 아니라 "구조로 기대되는 매출"을 써서 일시적 변동을 줄임
- **의외성 U** (v0 가중치)

| 성분 | 가중 | 뜻 |
|---|---:|---|
| 저유입 잔차 | 0.30 | 구조에 비해 사람이 덜 감 |
| 새로움 | 0.20 | 직전 분기 매출이 낮음(비인기) |
| 범주 거리 | 0.25 | 업종 구성이 관성 상권과 다름 |
| 공간 거리 | 0.25 | 관성 상권에서 멂 |

- **점수** S = R × U, R이 목적 안 하위 60%면 제외 → 목적마다 315곳 남음
- **MMR**(λ=0.7): 업종·거리가 비슷한 상권이 몰리지 않게 다양성 조정

**자체 검토로 고친 것**
- 이태원·동대문패션타운이 '덜 알려짐' 1위권으로 나옴
  - 원인: 유입이 행정동 단위 배분값 → 같은 동 상권은 점포 수와 무관하게 유입이 같음 → 큰 상권이 가짜 저유입
  - 조치: 새로움 항(비인기) 추가
- ILD 계산 척도 오류, 민감도 K 비교 오류, 테스트 대상 선택 오류 수정

**결과 (v0, 동대문구 출발)**
| 목적 | 상위 3곳 | 비교: 인기순 상위 |
|---|---|---|
| 식사 | 상계역, 동원전통종합시장, 수유역 | 명동 관광특구, 홍대입구역, 잠실 |
| 카페 | 공릉역 2번, 수유역, 이태원 관광특구 | 명동, 시청역, 홍대입구역 |
| 쇼핑 | 동원전통종합시장, 이태원역, 수유역 | 노량진역, 잠실, 명동 |

**검증 (라벨 없이 가능한 것만)**
- 프록시 라벨 백테스트: 평균 회귀에 오염돼 모든 방법이 무작위 수준 → 성능 주장 안 함
- beyond-accuracy: 관성 겹침률 0, 평균 거리 5.4km(인기순 7.2km, 거리순 0.5km 사이), ILD 0.257(인기순 0.230보다 높고 거리순 0.274보다 낮음)
- 반사실 시뮬레이션: 유입 5·10·20%가 추천으로 옮겨갈 때 도시 쏠림(지니) 변화
- 민감도: U 가중치가 결과를 가장 크게 흔듦
- 라벨 확보안: Kotkov식 3문항 설문(몰랐다 / 예상 밖이다 / 가 보고 싶다), 팀원 블라인드 평가, 다음 기간 유입 증가 사후 확인

**다음 단계로 넘어간 판단**
- 설계 표에 논문 12편을 근거로 적었으나 원문을 읽지 않고 씀 → 근거 확인이 먼저

### Phase 3: 선행연구 검증 → SERP v1 재설계
**문서**: `[serendipity] docs/serendipity/prior_research_notes.md`, `[serendipity] docs/serendipity/model_explained.md`, [`service_ideas.md`](service_ideas.md) · 11/2~3

**이유/판단**
- 발표·심사에서 "이 논문이 근거"라고 말하려면 원문 확인이 필수
- 틀린 근거 위에 가중치를 정하면 설계 자체가 흔들림

**진행 방식**
- 1차 노트: 서지 특정 + 초록 수준 판정(원문 호스트 접속 차단 상태), 기억 의존 내용은 [미확인] 표시
- 해설서: 이후 열린 원문(Kotkov 학위논문, PMC9008453 등)으로 보완, 확인 수준(원문/초록/2차/미확인) 표기
- 논문 → 설계 요소 대응표 작성, 근거 강도(직접 근거 / 해석·영감 / 근거 아님) 구분

**발견 (설계 문서 서술 판정)**
| 기존 서술 | 판정 | 실제 |
|---|---|---|
| Kotkov: 세렌디피티 = 관련성 × 새로움 × 의외성, 곱 형태 | 부분적으로 틀림 | 세 성분의 조합(AND)과 8가지 변형. 곱은 우리 설계 선택 |
| Kotkov의 novelty = 비인기 | 부분적으로 틀림 | "사용자가 몰랐다". 비인기는 집단 대리변수 |
| arXiv 2507.03503 = 기대 대비 인기 잔차 보정 | 틀림 | 보정 인기도(CP) 재정렬 논문(Forster 외, RecSys 2025) |
| Mobile Personal Guide (MDM 2016) | 서지 오류 | "MPG: Not So Random Exploration of a City" |

- 설계에 영향을 준 결과
  - Kotkov 2018: 의외성의 한 변형은 만족도를 떨어뜨림
  - DISCOVERY 2024: 세렌디피티 모형이 오히려 **가까운 POI를 선호** → v0의 "멀수록 가점"과 반대

**v1 재설계**
- 문제: 관성(특히 거리순)이 출발지 옆에 몰려 있어서, v0는 "가까운데 안 가 본 곳"을 감점함
- 관성 이탈을 두 종류로 구분: ① 가까운데 안 가 본 곳 ② 멀지만 의외로 괜찮은 곳

| 항목 | v0 | v1 |
|---|---|---|
| U 가중치(잔차·새로움·범주·공간) | 0.30·0.20·0.25·0.25 | 0.45·0.20·0.35·**0** |
| 관성 상권 | 점수로만 밀어냄 | 추천에서 제외 |
| 선정 방식 | 전체 상위 10 | 이동시간 구간별 3곳: ≤15분 / 15~22분 / 22~30분 |
| 출발지 | 동대문구 | 동대문구 + 한국외대 서울캠 |

- v1 서울캠 출발 식사 예시: 태릉시장 특화거리(14분), 청량리전통시장(16분), 창신골목시장(24분 측정)

**후속 아이디어 (구현 안 함)**
- 콜드 스타트: 첫 실행 때 카드 5장으로 "가 봤어요 / 처음 봐요 / 가고 싶어요"를 물어 개인 관성 생성
- 맥락 추천: 비 오는 날 실내형 상권(지하상가, 시장 아케이드) 가점, 저녁 여가 가중
- 데이터 교체: B078 생활이동 OD, B079 카드소비, ODsay 실측, 인지도 설문

**다음 단계로 넘어간 판단**
- 상권 폴리곤이 넓음: 대각선 중앙값 골목 605m, 발달 879m, 관광특구 1.7km(최대 4.1km)
- "이태원 관광특구가 의외의 장소"만으로는 어느 가게로 갈지 모름 → **가게 단위까지 내려가야 행동으로 이어짐**

**문서**: `[store-level] docs/store_level/recommendation_options.md`, `docs/store_level/validation_v0.md`, `[store-level] docs/store_level/v1_changes.md` · 11/2~3

**이유/판단**
- 점포별 매출·방문·평점 공개 데이터 없음 → 가게의 '매력'을 직접 잴 수 없음
- 대신 공공데이터는 '새로움'(비프랜차이즈, 희소 업종, 노포)에 강함
- 따라서 역할 분리: **매력은 상권 모형(R)에서 상속, 가게 단계는 새로움·의외성 위주**

**검토한 대안**
| 안 | 내용 | 판단 |
|---|---|---|
| A. 점포 규칙 점수만 | 30분 안 모든 점포를 규칙으로 정렬 | 기각. 상권 매출 모형을 버림, 후보 수만 곳, 노포 많은 종로·청계에 쏠림(태그 수와 점포 수 상관 0.75) |
| **B. 2단계 결합** | SERP로 상권 선정 → 상권 안 가게를 규칙 점수로 재정렬 | **채택**. 기존 자산 재사용, 후보 약 1,500곳으로 검수 가능, "왜 이 상권 + 왜 이 가게" 설명 가능 |
| C. B + 조건부 로짓 | 설문 라벨로 가중치 추정 | 라벨 확보 후 진행 |

**진행 방식**
- **서울 점포 테이블 v0** (로컬, 원천 커밋 금지)
  - 상가정보 55만 건 ↔ 인허가 일반·휴게·제과 매칭(80m 안 + 상호 유사도 0.6)
  - 태그: 노포(≤2005), 10년+(2006~2015), 오래된 카페, 착한가격, 상권 안 희소도, 프랜차이즈
  - 착한가격 좌표: 카카오 응답은 저장·재사용 제한 → 공공데이터 안 주소-좌표 쌍으로 대체(2,176/2,210곳, 카카오 좌표와 중앙값 0.6m 차이)
- **가게 점수**
  - gate: 목적 업종 ∧ 영업 중 ∧ 비프랜차이즈 ∧ 상권 대표점에서 도보 10분 안
  - r_store(관련성) = 0.6 × 영업연수 백분위(같은 소분류 안) + 0.4 × 착한가격·오래가게
  - u_store(의외성) = 0.4 × 희소도 + 0.3 × 노포·10년+ + 0.3 × 관성 업종과의 거리
  - 상권마다 MMR로 3곳(같은 소분류 1곳), 목적별 최대 30곳
- 출발점 동대문구로 통일(11/3 팀 결정) → 후보 제외율 4.3%(서울캠 기준이면 73.5%)

**결과 (v0)**
| 목적 | 추천 수 | 관성 상권 겹침 | 업종 다양성(ILD) |
|---|---:|---:|---:|
| 식사 | 30 | 0 | 0.952 |
| 카페 | 21 | 0 | 0.652 |
| 공부 | 25 | 0 | 0.847 |
| 쇼핑 | 30 | 0 | 0.977 |
| 여가문화 | 24 | 0 | 0.935 |

- 매칭 감사 50곳: 맞음 47, 애매 3, 틀림 0 → 정밀도 0.94 이상(Claude 1차 판정, 사람 검수 전)
- 민감도: 가중치 ±0.1에 상위 집합 자카드 0.82~1.0
- **설문 카드 30세트 × 20장**
  - 의외성 10장 + 기준선 10장(대표점 근처 / 무작위 / 관성 상권) 무작위 혼합
  - 출처 노출 편향 발견: 공공 태그 카드 비율이 의외성 0.75 vs 근처 0.23 → 이유 문장은 Q4에서만 공개, `has_tag`를 공변량으로 분석

**v0 결과를 보고 고친 것 (v1 규칙, 코드·테스트 완료, 미실행)**
| 문제 | 예 | 고침 |
|---|---|---|
| 찾아갈 곳이 아닌 가게가 '희소 업종'으로 상위 | 출장열쇠집(쇼핑 2위), 재활클리닉(여가 1위), PC방 | 비목적지 제외, 희소도 가점은 목적지형 업종에만 |
| 업종 오분류 | 마이보쌈 → 일식, 킹스컵밥 → 커피숍 | 상호 키워드 > 인허가 업태 > 상가정보 순 보정 |
| 공부 범위가 넓음 | 학원, 문구점, 스포츠강습 | 독서실·스터디카페·서점·북카페로 한정 |

- 사전 영향(v0 목록에 규칙만 덧씌운 추정): 상위 130곳 중 32곳 제외, 업종 보정 4곳, 쇼핑 희소 가점 상실 10곳

**리뷰 키워드 설계 (가게 성격 보강)**
- 공공데이터에 없는 것: 분위기, 혼밥, 조용함, 공부하기 좋음
- 네이버 플레이스 키워드 리뷰("조용해요", "혼밥하기 좋아요")의 **집계 수만** 사용, 본문·닉네임·사진 미수집
- 계산: 키워드 비율 → 업종 평균으로 축소(리뷰 적은 가게 보호) → 같은 업종 대비 lift → 10개 테마 점수
- 반영: 목적 적합(fit)을 r_store에, 관성 상권 가게와의 성격 차이를 u_store에
- 리뷰 20건 미만 가게는 업종 평균으로 두고 제외하지 않음(노포 불이익 방지)

**다음 단계로 넘어간 판단**
- 네이버 키워드 집계 수집 실측: **캡차 토큰 없이는 첫 요청부터 429**, 헤더를 맞추고 간격을 20초 이상으로 늘려도 동일
- 결과: 모든 가게 `review_evidence=low`, 리뷰 항 0.5 고정 → 테마 검증·카페 공부 추천 불가
- 리뷰를 얻을 다른 경로 조사 필요

### Phase 5: 리뷰 수집 경로 조사
**문서**: [`research_log.md`](research_log.md) 5장 · 11/3

**이유/판단**
- Phase 4의 리뷰 항을 채울 경로 확보
- 기준: 대회 규정에 리뷰 수집 금지 조항 없음(11/3 팀 확인) → Phase 1의 "공공데이터만" 원칙 대체

**진행 방식**
- **선행 사례 조사**

| 방식 | 내용 | 평가 |
|---|---|---|
| Selenium 크롤링 | 리뷰 페이지에서 '더보기' 반복 클릭 | 느림, 화면 바뀌면 깨짐 |
| 내부 요청 호출 | 개발자도구에서 찾은 요청을 직접 호출 | 빠르지만 차단에 취약 |
| 유료 도구 | Apify, 크롬 확장(SellFit 등) | 소량에 적합 |
| 공식 API | 네이버 검색(블로그·카페), 카카오 로컬 | 리뷰 본문 없음, 대신 안정적 |

- **mapjiri-datamining 검토**(카카오맵 리뷰 크롤러): 지역 × 메뉴 키워드 조합 구조는 참고할 만함, 코드는 옛 셀렉터·예외 은폐·라이선스 없음으로 재사용 불가
- **판례 확인**
  - 야놀자 vs 여기어때(대법원 2022): 공개 정보 크롤링 형사 무죄
  - 네이버 부동산 DB(특허법원 2026): DB 제작자 인정, 8,000만 원 배상
  - 흐름: 소량 분석은 비교적 안전, 대량 수집·재게시는 위험
- **robots.txt 실측**: 카카오맵·네이버 지도 모두 모든 봇 차단, GPTBot·ClaudeBot 등 AI 봇은 이름으로 지정 차단, 네이버는 "AI 학습·RAG 금지" 문구
- **로그인 토큰 검토**: 리뷰는 공개 데이터라 속도·양 이득 없음, 계정 제한 위험만 증가 → 사용 안 함

**결론**
- 리뷰 원문을 주는 공식 API 없음
- 크롤링은 소요 시간보다 **차단이 병목**(Phase 4 실측과 일치)
- **대안: 공식 API로 가게별 평판·키워드 생성**
  1. 카카오 로컬 API: 가게 목록·좌표
  2. 네이버 블로그 검색 API: "가게명 + 지역" 후기 제목·요약
  3. 협찬 글 제거("원고료", "제공받아") → 키워드 추출·긍부정 분류
- 기대: 동대문구 음식점 약 3,200곳을 하루 안에 처리
- 한계: 요약문이 짧고 협찬 편향, 메뉴별 세부 평가·별점은 어려움
- 부수 효과: 블로그 언급 수 = Phase 1에서 못 잰 '숨은 정도'의 직접 지표로 사용 가능

- **결과를 가장 크게 바꾸는 건 모델이 아니라 데이터의 현실성**
