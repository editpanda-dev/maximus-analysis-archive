# 서비스 적용 아이디어 모음

작성: 2026-11-03 (5장은 11-04) · 상태: 아이디어 모음(구현 안 함) · 옛 위치: `docs/serendipity/followup_ideas.md`

지금 모델(SERP-v1)은 그대로 둬요. 아래는 서비스에 붙여 볼 만한 후보를 모아 둔 거예요. 언제 무엇부터 할지는 [`roadmap.md`](roadmap.md)에 있어요. 위에 있을수록 먼저 검토할 만한 것이에요.

## 1. 콜드 스타트: 개인 기록 없이 기준점 세우기

지금은 "동대문구 출발 집단의 관성(거리순·인기순·과거 유입순 상위)"을 개인 기록 대신 기준점으로 써요. 이걸 바꾸거나 보강하는 방법들이에요.

### 1-1. 액티브 러닝으로 개인 기준 모형 만들기 (우선)

- 앱을 처음 켤 때 상권·가게 카드 5장 정도를 보여 줘요.
- 카드마다 두 가지를 물어요. 하나는 "가 봤어요 / 알아요 / 처음 봐요"이고, 다른 하나는 "가고 싶어요"예요.
- "가 봤어요·알아요"라고 답한 곳과 그와 비슷한 곳을 그 사람의 기준 모형(관성)으로 삼아요. Murakami·Ge 지표에서 말하는 primitive model이에요.
- 추천은 "기준 모형 밖 ∩ 가고 싶어요와 비슷한 곳"에서 해요.
- 카드는 성격이 많이 다른 곳(전통시장 / 카페거리 / 노포 / 대형 역세권)을 섞어 골라요. 그래야 응답 몇 개로 취향이 갈려요.
- 응답 구조가 Kotkov 2018 설문(새로움·의외성·관련성)과 같아서, 쌓이면 검증 라벨로 그대로 쓸 수 있어요.

### 1-2. 맥락(날씨·시간대) 기반 추천 (우선)

- 날씨, 시간대, 요일 같은 지금의 상황을 기준점에 더해요.
- 예를 들어 비 오는 날에는 실내형 상권(지하상가, 전통시장 아케이드, 복합몰)에 가점을 줘요. 저녁에는 여가문화 목적의 가중을 올려요.
- 이미 가진 것: 08·14·19시 도달률(PATH-v0). Chowdhury 등(2020)은 출발 시각과 목적지 선택이 강하게 엮여 있다고 보고했어요.
- 필요한 것: 날씨 데이터(기상청 예보 API 등, 이용 조건 확인 필요)와 상권별 실내·실외 구분 태그.
- 맥락별로 관성도 따로 잡을 수 있어요. "비 오는 저녁에 보통 가는 곳"과 다른 곳을 추천하는 식이에요.

### 1-3. 나머지 (참고)

| 방법 | 한 줄 | 판단 |
|---|---|---|
| 인구통계 집단 기준점 | 성별·연령 집단의 평균 취향을 기준으로 삼아요 | 보류. 찾은 자료(Erasmus 학위논문 2019)는 인구통계를 넣으면 새로움이 줄었다고 해요 |
| 지식 그래프·온톨로지 | 상권-업종-점포 관계를 타고 "연결은 있지만 분야가 다른 곳"을 찾아요 | 참고. Kuznetsov(2023) 온톨로지 기반 콜드 스타트 세렌디피티 논문이 있지만 본문은 미확인이에요 |
| 밴딧(탐색) | 추천 일부를 새 후보에 할당해 반응을 보며 배워요 | 서비스를 실제로 운영한 뒤에 해요. 탐색만으로는 관련성이 보장되지 않아요 |

## 2. 롱테일 × 관련성: 덜 알려졌는데 갈 만한 곳

### 문제

v1 상위 10곳이 사실상 인기 상권이에요. 식사 상위 10곳의 목적 매출 인기 백분위 중앙값은 0.87이고, 인기 하위 50%인 곳은 0곳이에요. R이 "구조로 예측한 매출"이라 인기와 같이 움직이기 때문이에요.

"인기 하위 50% ∩ R ≥ 0.6" 칸은 작아요. 식사 36곳, 카페 49곳, 쇼핑 42곳, 여가문화 29곳이에요(786곳 중, 2025년 4분기).

예시:
- 식사: 홍릉시장, 서울숲카페거리, 간데메공원
- 카페: 화양사거리, 자양4동주민센터
- 쇼핑: 평화시장, 마장축산물시장, 능동로골목시장

### 후보 방법

- **R을 규모가 아니라 질로 재기**: 점포당 매출, 업종 비중, 영업 지속기간처럼 큰 상권이 저절로 이기지 않는 값을 써요.
- **인기 구간별 자리 나누기**: 추천 10곳 중 몇 곳은 꼬리 칸에서 고르게 해요. Forster 등(2025)의 인기 보정과 같은 생각이에요. 지금 `band_picks`(이동시간 구간별 3곳)와 같은 구조예요.
- 어느 쪽이든 꼬리 칸의 R은 예측값이에요. 설문 "가 보고 싶나요" 점수로 관련성이 무너지지 않는지 확인해야 해요.

## 4. 상권 단위 다시 정하기

- 지금은 서울시 공식 상권 폴리곤 1,650개 중 접근률 25% 이상인 786개가 후보예요(`docs/commercial_area_definition.md`, editpanda-dev 저장소 `codex/geonwoo/meal-shopping-v1`).
- 관광특구는 폴리곤이 너무 넓어요(중앙값 대각선 1.7km, 최대 4.1km). "이태원 관광특구"만으로는 어디로 가야 할지 알 수 없어요.
- 글로벌캠(모현)에서는 공식 상권이 없어서 점포 좌표를 DBSCAN으로 묶어 상권을 새로 만들었어요(반경 100m, 1.5km 넘게 길면 60m로 다시 나눔, 30점포 이상). 같은 방법으로 서울의 넓은 상권을 쪼개는 걸 검토할 수 있어요.

## 5. 사용자 니즈 시나리오로 목적 세분화

지금 목적은 식사·카페·쇼핑·여가문화·공부 다섯 개뿐이에요. 하지만 같은 '카페'라도 혼자 공부하러 가는지, 데이트하러 가는지에 따라 좋은 곳이 완전히 달라요. 그래서 먼저 사용자가 어떤 니즈로 가게를 찾을지 예상해 보고, 그 니즈를 데이터로 어떻게 표현할지 정리했어요.

대상은 한국외대 서울캠 학생으로 가정했어요. 아래 니즈와 가중치는 모두 가설이고, 설문으로 확인해야 해요.

### 5-3. 데이터로 표현하는 방법

니즈 하나를 **꼭 맞아야 하는 조건(거름)**과 **선호 점수(가중합)**로 나눠요. 시나리오마다 조합을 미리 정해 두고, 사용자는 시나리오만 고르면 돼요.

```
후보     = 이동시간 ≤ 허용 시간  AND  그 시간대 영업 가능성 있음  AND  예산 범위
선호 점수 = Σ w_k × 신호_k        (k = 시나리오별 신호, w = 시나리오별 가중치)
```

선호 점수는 지금 모델의 관련성 R 자리에 넣고, 의외성 U와 이동시간 구간 추천(`band_picks`)은 그대로 써요.

조건별로 쓸 수 있는 데이터 신호예요. 상태는 ○ 저장소에 있음, △ 원천이 레포 밖(로컬)에 있거나 열이 있는지 확인이 필요함, × 공공데이터로는 불가예요.

| 니즈 조건 | 데이터 신호 | 단위 | 상태 |
|---|---|---|---|
| 혼자 | 건당 결제액 낮음, 평일 비중 높음 | 상권 | ○ 상권 추정매출 원본 |
| 여럿·모임 | 건당 결제액 높음, 시설 규모(㎡) 큼 | 상권 / 점포 | ○ / △ 휴게·일반음식점 인허가 |
| 공부 | 스터디카페 위치, 독서실, 도서관·열람실 | 점포·시설 | ○ 카카오 스냅샷·공공시설 |
| 분위기·데이트 | 주말 비중, 20~30대 비중, 400m 안 공원·전시·영화관 | 상권 | ○ |
| 빨리·테이크아웃 | 프랜차이즈 여부, 06~11시 매출 비중, 등굣길 위 여부 | 점포 / 상권 / 경로 | △ / ○ / △ |
| 심야 | 21~06시 매출 비중 | 상권 | ○ (가게 영업시간은 ×) |
| 가성비 | 착한가격업소, 건당 결제액 | 점포 / 상권 | △ / ○ |
| 단체·예약 | 시설 규모, 업태(호프·한식 등) | 점포 | △ |
| 지역 명물·노포 | 인허가 개업일, 비프랜차이즈 | 점포 | △ (지위승계로 개업일이 남는 오류 있음) |
| 이동 허용 | 이동시간 구간 | 상권 | ○ (실측은 서울캠 60곳뿐) |
| 새로움 욕구 | 의외성 U, 관성 상권 제외 | 상권 | ○ 이미 구현 |
| 콘센트·와이파이·조용함·좌석 | 없음 | — | × 리뷰 크롤링 금지라 설문·현장 확인만 가능 |

상권 신호의 출처는 저장소에 이미 있는 `data/raw/commercial_area/commercial_sales_2025.zip`(서울시 상권분석서비스 추정매출)이에요. 업종별로 주중·주말, 요일, 시간대 6구간, 성별, 연령대 6구간 매출 금액과 건수가 있어요.

| C1 공강 카공 | 15분 이내, 평일 14~17시 매출 있음 | 낮은 건당 결제액 0.3, 평일 비중 0.2, 스터디카페 밀도 0.2, 20대 비중 0.2, 소형 비프랜차이즈 0.1 |

### 5-4. 시험 계산(카페, 서울캠 30분 안, 2025년 4분기)

구현 전에 상권 단위 신호만으로 카페 세부 프로필이 서로 다른 곳을 잡는지 봤어요. 카페 매출이 있는 161곳 중 월 1,000건 이상인 149곳이 대상이에요.

- 혼카페 = 평일 비중 0.3 + 낮은 건당 결제액 0.3 + 20대 비중 0.2 + 14~17시 비중 0.2
- 데이트 = 주말 비중 0.35 + 높은 건당 결제액 0.25 + 20~30대 비중 0.25 + 17~21시 비중 0.15
- 심야 = 21~06시 매출 비중
- 아침 = 06~11시 매출 비중

프로필끼리 순위 상관(스피어만)이 −0.59~0.32라서 서로 다른 축을 잡았어요. 데이트와 아침은 −0.59, 혼카페와 데이트는 −0.41이에요.

| 프로필 | 상위 3곳 | 근거 |
|---|---|---|
| 혼카페 | 월곡역, 동평화시장, 안암역 3번 (4·5위 서울시립대, 회기역 1번) | 건당 3,500~5,100원, 주말 10~24% |
| 데이트 | 상봉역 4번, 텃골근린공원, 종암동주민센터 | 주말 40~44%, 20~30대 67~76%, 건당 9,900~16,600원 |
| 심야 | 태릉시장 특화거리, team204, 장평중학교 | 21~06시 매출 37~47% |
| 아침 | 중랑노인종합복지관, 장스여성병원, 미아사거리 | 06~11시 매출 32~40% |

이 결과는 스크립트로 저장하지 않은 일회성 확인이에요.

### 5-5. 한계

- **표현하지 못하는 니즈가 많아요.** 콘센트, 소음, 좌석, 분위기처럼 카공·데이트에서 가장 중요한 조건이 공공데이터에 없어요.
- **상권 신호는 평균이에요.** 같은 상권 안에 혼카페와 데이트 카페가 섞여 있어요. 가게를 고르려면 점포 단위 신호(△)가 있어야 해요.
- **결제 데이터는 결제한 사람 기준이에요.** 2명이 와도 1명이 내면 1건이라, '건당 결제액이 높다 = 여럿이 왔다'는 추정일 뿐이에요.
- **업종이 섞여 있어요.** '커피-음료'에 주점성 음료점이 섞인 듯해요. 태릉시장 특화거리는 건당 27,355원에 밤 매출이 47%예요. 건당 금액 상한이나 업종 분리가 필요해요.
- **가게별 영업시간은 공공데이터에 없어요.** 심야 매출 비중은 '늦게 여는 가게가 있을 가능성' 정도만 알려 줘요.
- **결제가 적은 상권은 비율이 흔들려요.** 시험 계산에서는 월 1,000건 미만을 뺐어요.

### 5-6. 확인하고 진행하는 순서

1. **설문으로 니즈 확인**(학생 30~50명, 1-1의 카드 설문과 Kotkov 3문항에 붙여요)
   - 최근 한 달 시나리오별 방문 횟수 → 시나리오 우선순위
   - 시나리오별로 중요한 조건 고르기(최대 3개, 또는 MaxDiff) → 가중치 근거
   - 허용 이동시간, 예산
   - 늘 가는 곳 3곳 → 실제 관성. 회기역처럼 거리순 상위 10곳에 안 걸리는 단골 상권 문제도 풀려요
2. **지금 데이터로 잘 표현되는 시나리오부터 구현**: C1 공강 카공, C5 데이트, M5 야식
3. **점포 단위 신호 붙이기**: 휴게·일반음식점 인허가의 업태·시설 규모(로컬 실행 필요, `docs/store_level/` 참고)
4. 1-2의 맥락(시간대·날씨)과 합쳐요. 예: 지금 21시면 심야 비중을 R에 곱해요.
