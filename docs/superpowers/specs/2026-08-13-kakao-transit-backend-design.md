# 어디가지 — 카카오 대중교통 백엔드 설계

## 목표

대한민국 내 선택 출발지에서 카페 등 목적별 장소를 카카오 장소 검색으로 찾고, 카카오 대중교통 경로 결과를 기준으로 최대 이동시간 안의 추천만 반환한다. iOS는 카카오 키를 절대 보유하지 않는다.

## 문제와 원칙

기존 MapKit 경로는 Apple 데이터 제공 범위와 현재 선택 좌표에 따라 0건이 될 수 있다. 카카오 REST API는 키워드 장소 검색 및 출발/도착 좌표 기반 대중교통 경로를 제공하므로 국내 추천 계산의 제공자로 사용한다. 카카오가 경로를 반환하지 않거나 시간이 초과하면 결과를 만들지 않는다.

## 경계

- iOS: 현재 위치·검색·지도 핀으로 출발 좌표를 확정하고 `POST /v1/live-recommendations`만 호출한다.
- FastAPI: 환경변수 `KAKAO_REST_API_KEY`를 읽고 `Authorization: KakaoAK <key>`로 카카오 API를 호출한다.
- 카카오: 장소 검색과 대중교통 경로 계산만 담당한다.
- 기존 fixture `/v1/recommendations`는 별도 데모 엔드포인트로 유지하며 자동 대체하지 않는다.

## API 계약

요청:

```json
{
  "origin_name": "한국외국어대학교 글로벌캠퍼스",
  "origin_latitude": 37.334,
  "origin_longitude": 127.267,
  "purpose": "cafe",
  "max_travel_time_minutes": 30
}
```

응답은 `provider: "kakao"`, `queried_at`, 장소명·주소·좌표·예상 총시간·거리·경로 단계와 제한사항을 포함한다. 카카오 응답이 보장하지 않는 실시간 도착예정, 혼잡도, 요금, 환승 보장은 반환하지 않는다.

## 처리 흐름

1. 좌표가 대한민국 유효 범위 밖이면 422로 거절한다. 이로써 과거 Simulator의 샌프란시스코 핀 상태가 국내 추천으로 처리되지 않는다.
2. 목적별 키워드로 카카오 장소 검색을 호출하고, 출발 좌표 주변 반경·거리순으로 후보를 받는다.
3. 최대 4개씩 카카오 대중교통 경로 API를 호출한다.
4. 경로가 없거나 가장 빠른 경로가 상한을 넘으면 제외한다.
5. 남은 후보를 예상시간·거리·장소명으로 안정 정렬해 최대 5개 반환한다.

## 오류·보안

- API 키 미설정은 서버 시작/요청 시 명확한 구성 오류로 처리하며 키 값은 로그·응답에 노출하지 않는다.
- 카카오 401/403/429/5xx는 제공자 오류로 구분해 iOS에 재시도 가능한 메시지를 준다.
- 위치 좌표는 추천 요청 목적으로만 카카오에 전달되며 앱 자체 DB에 저장하지 않는다.
- `.env`는 Git 추적하지 않는다.

## 검증

- HTTP mock으로 Authorization 형식, 목적별 검색어, 국내 좌표 검증, 대중교통 전용 경로, 30분 포함/초과 제외, 0건·공급자 오류를 테스트한다.
- iOS 모델/클라이언트 테스트로 요청 snake_case, 성공·오류 렌더링, fixture 비대체를 검증한다.
- 실제 키로 `/healthz`와 제한된 카카오 통합 smoke test를 실행하되 키를 출력하지 않는다.
