# 어디가지 — MapKit 실시간 추천 설계

## 목표

출발지를 현재 위치, 장소 검색, 지도 핀으로 확정하고, 그 좌표 주변의 목적별 장소를 MapKit으로 검색한다. 각 후보는 MapKit 대중교통 경로를 계산한 뒤 선택한 최대 이동시간 안의 후보만 결과에 표시한다. 출발지가 달라지면 후보와 경로가 반드시 달라져야 한다.

## 범위

- 앱 시작 시 위치 권한을 요청하고 허용 시 현재 위치를 출발지로 사용한다.
- 사용자는 출발지 텍스트 검색을 통해 장소를 선택할 수 있다.
- 사용자는 지도 화면에서 핀을 이동해 상세 출발 좌표를 확정할 수 있다.
- 목적별 검색어(맛집, 카페, 데이트, 쇼핑, 문화, 휴식)를 출발지 인근에 적용한다.
- 각 장소에 대해 대중교통 `MKDirections`를 요청하고, 예상 총 소요시간과 단계별 이동수단을 표시한다.
- 제한시간을 넘거나 대중교통 경로가 없는 후보는 실시간 결과에서 제외한다.
- 결과를 누르면 Apple 지도에서 해당 출발지와 목적지의 경로를 연다.
- 기존 FastAPI fixture API는 별도 데모 모드로 남기며 실시간 결과의 자동 대체값으로 사용하지 않는다.

## 아키텍처

`LocationService`가 위치 권한과 현재 좌표를 관리한다. `OriginSearchService`가 `MKLocalSearchCompleter` 및 `MKLocalSearch`로 검색 결과를 좌표화한다. 지도 선택 화면은 `MapKit.Map` 및 annotation으로 선택 좌표를 반환한다.

`LiveRecommendationService`는 목적별 검색어로 `MKLocalSearch`를 수행하고, 결과별 `MKDirections.Request.transportType = .transit`을 병렬 제한 처리한다. 각 경로의 `expectedTravelTime`, `steps`, `distance`를 `LiveRecommendation`으로 변환한다. 서비스는 경로가 확인된 후보만 반환하며, 결과는 목적 일치도, 이동시간, 이름 순으로 안정적으로 정렬한다.

`RecommendationViewModel`은 출발지 상태를 좌표 기반으로 보관하고, 실시간 모드에서 이 서비스를 호출한다. 위치 권한 거부, 검색 결과 없음, 대중교통 경로 없음, 네트워크 오류는 서로 다른 사용자 메시지와 재시도 동작을 제공한다.

## UI 흐름

1. 앱 시작: 현재 위치 사용을 요청한다. 허용 시 “현재 위치”가 선택된다.
2. 출발지: 검색 입력 또는 “지도에서 상세 위치 지정”으로 변경한다.
3. 목적·시간 선택 후 추천: 로딩 중에는 검색·경로 계산 상태를 표시한다.
4. 결과: 장소명, 주소/지역, 총 예상시간, `도보 → 버스/지하철 → 도보` 단계, 환승 정보와 거리 표시.
5. 상세: 카드 탭으로 Apple 지도 경로를 연다. 상단 “조건으로”는 검색 화면으로 돌아간다.

## 데이터 및 투명성

- 실시간 결과에는 `Apple MapKit 기준 예상 경로`와 조회 시각을 표시한다.
- MapKit이 제공하지 않은 도착예정시각, 혼잡도, 요금, 환승 보장 정보는 만들지 않는다.
- 대중교통 경로가 없는 경우 다른 교통수단으로 자동 전환하지 않는다.
- 위치는 디바이스에서만 사용하며 서버로 전송하지 않는다.

## 오류 처리

- 위치 권한 거부: 검색 또는 지도 핀 선택을 안내한다.
- 검색 결과 없음: 검색어 수정 안내.
- 경로 없음/시간 초과: 조건 완화 또는 다른 출발지 선택 안내.
- 네트워크 오류: 마지막 결과를 실시간인 것처럼 재사용하지 않고 재시도만 제공한다.

## 검증

- 위치 서비스와 검색/경로 서비스를 protocol로 분리하고 XCTest stub으로 검증한다.
- 출발 좌표가 달라지면 후보 검색 요청 중심점이 달라지는지 검증한다.
- transit 경로만 통과시키고 제한시간 초과 후보를 제거하는지 검증한다.
- 결과의 이동 단계와 Apple 지도 deep link 생성 규칙을 검증한다.
- 실제 Simulator에서 위치 권한, 검색 위치, 핀 위치 각각으로 추천을 실행한다.
