# 리서치 진행 로그 요약 (건우)

기준: 2026-11-03 · 상세 기록: [`gunwoo_research_log.md`](gunwoo_research_log.md)

## 1. 배경 및 핵심 방향성 (Direction)

**[진행 목적]**
- 막시무스의 상권 랭킹 방법을 "학생이 실제로 갈 만한, 몰랐던 곳" 추천으로 확장함
- 1차 활용처: 2026 AI 캠퍼스 바이브코딩 경진대회 (기획서 마감 11-10)

**[핵심 방향성]**
- 인기순 추천이 아님 → **"늘 가던 곳(관성)과 다르지만 갈 만한 곳"** 추천
- 단위를 점점 좁힘: 캠퍼스 생활권 → 서울 상권 786곳 → 상권 안 가게
- 공공데이터 우선, 리뷰는 보조 신호로만 사용
- 정답 라벨이 없으므로 정확도는 주장하지 않음 → 설문으로 검증

**[전체 궤적 한 줄]**
캠퍼스 30분 숨은 곳 (10/29~31) → 상권 의외성 모델 SERP (11/2) → 선행연구 검증 후 v1 재설계 (11/2~3) → 점포 단위 추천 (11/2~3) → 리뷰 수집 경로 조사 (11/3)

## 2. 논리 흐름 및 전개 과정 (Logical Flow)

### Phase 1: 글로벌캠퍼스(용인 모현) 30분 숨은 곳 탐색
- **이유/판단**
  - 대회 주제에 맞춰 동대문 상권 방법을 글캠 출발로 이식함
  - "글캠 주변에 갈 곳이 없다"는 통념을 데이터로 확인하려 함
- **진행 방식**
  - 대중교통 30분 도달 모형 구축: GBIS 노선망, ODsay 실측 13곳으로 보정(평균오차 3.1분)
  - 숨은 가게 태그 부여: 인허가 기반 노포, 개인카페, 희소 업종
  - 같은 방법을 서울캠에 적용: 인허가 16만 건, 상권 786곳
- **결과**
  - 30분 생활권은 모현읍·오포뿐임 (12km 안 점포의 10%)
  - 배차 대기를 넣으면 30분 안 상권이 11곳에서 6곳으로 줄어듦 → 결론을 가장 크게 바꾸는 변수
  - 숨은 가치는 명소가 아니라 상권 안 노포에 있음 (오포 일대)
- **다음 단계로 넘어간 판단**
  - "노포 = 숨은 곳"은 대리 지표일 뿐임 → '숨은'을 측정할 정의가 필요함
  - 인기도 데이터가 없음 → "관성 대비 의외성"으로 문제를 재정의

### Phase 2: 상권 단위 의외성 추천 모델 (SERP v0)
- **이유/판단**
  - '숨은'을 "집단의 관성(거리순·인기순·과거 유입순)이 추천하지 않는 곳"으로 정의함
  - 개인 이력이 없음 → 동대문구 출발 집단 기준의 의외성으로 한정함
- **진행 방식**
  - 관련성 R: 상권 구조로 예측한 목적 매출 + 30분 도달률
  - 의외성 U: 저유입 잔차 + 비인기 + 업종 구성 거리 + 공간 거리
  - 점수 S = R × U, R 하위 60%는 제외 (관련 없는 의외성 차단)
  - MMR로 다양성 조정, 목적 5개(식사·카페·쇼핑·여가문화·공부)
- **검증**
  - 라벨 없이 가능한 것만 수행: 프록시 백테스트, beyond-accuracy 지표, 반사실 시뮬레이션, 민감도
  - 프록시 백테스트는 평균 회귀에 오염됨 → 성능 주장 안 함
- **다음 단계로 넘어간 판단**
  - 설계 근거로 인용한 논문 서술을 원문으로 확인할 필요가 생김

### Phase 3: 선행연구 검증 → v1 재설계
- **이유/판단**
  - 설계 문서가 논문 12편을 원문 확인 없이 인용함 → 근거부터 확인함
- **진행 방식**
  - 서지 특정, 초록·원문으로 서술 판정
  - 팀원·심사위원용 해설서 작성 (논문 → 설계 요소 대응표)
- **발견**
  - Kotkov의 '곱 형태'는 원문 주장이 아님 (원문은 세 성분의 조합과 변형)
  - 인용한 인기도 보정 논문은 다른 방법(CP 재정렬)이었음
  - 세렌디피티 모형이 오히려 가까운 곳을 선호한다는 결과가 있음 → v0의 "멀수록 가점"과 반대 방향
- **v1 변경**
  - 공간 거리 가점 제거
  - 관성 상권은 추천에서 아예 제외
  - 이동시간 구간별로 3곳씩 선정: 가까운데 안 가 본 곳(≤15분) / 중간(15~22분) / 멀지만 의외로 괜찮은 곳(22~30분)
  - 서울캠 출발 옵션 추가
- **다음 단계로 넘어간 판단**
  - 상권 폴리곤이 넓음 (관광특구 대각선 1.7km) → "이 상권이 의외"만으로는 어느 가게로 갈지 모름

### Phase 4: 점포 단위 추천
- **이유/판단**
  - 추천의 최종 단위는 가게여야 행동으로 이어짐
  - 점포별 매출·평점 공개 데이터가 없음 → 상권은 SERP로 고르고, 가게는 공공데이터 규칙으로 고르는 2단계 구조 채택
- **진행 방식**
  - 서울 점포 테이블 구축: 상가정보 55만 건 + 인허가 3종 + 착한가격 (카카오 좌표 대신 공공 좌표)
  - 가게 점수: 영업 지속기간·착한가격(관련성) × 희소도·노포·관성 업종과의 거리(의외성)
  - 상권마다 3곳, 최종 30곳 선정
  - 설문 카드 30세트 제작 (의외성 10장 + 기준선 10장, 출처 노출 편향 통제)
  - v1 규칙 추가: 비목적지(열쇠집·병원 등) 제외, 업종 오분류 보정, 공부 범위 축소
- **결과**
  - 매칭 정밀도 0.94 이상 (Claude 1차 판정)
  - 추천 가게 전부 관성 상권 밖에서 나옴
  - 가게 성격(분위기·혼밥·공부)은 공공데이터로 알 수 없음 → 리뷰 키워드가 필요함
- **다음 단계로 넘어간 판단**
  - 네이버 키워드 리뷰 집계 수집 시도 → 캡차 토큰 없이는 첫 요청부터 429 차단됨
  - 리뷰를 얻을 다른 경로를 조사함

### Phase 5: 리뷰 수집 경로 조사
- **이유/판단**
  - 점포 점수의 리뷰 항이 모두 비어 있음 (0.5) → 채울 경로 필요
  - 기준: 대회 규정에 리뷰 수집 금지 조항 없음 (11/3 팀 확인)
- **진행 방식**
  - 선행 사례 조사: Selenium 크롤링, 내부 요청 호출, 유료 도구, 공식 API
  - 관련 판례 확인: 공개 정보 소량 분석은 비교적 안전, 대량 수집·재게시는 위험
  - robots.txt 실측: 카카오맵·네이버 지도 모두 모든 봇 차단, AI 봇은 이름으로 지정 차단
- **결론**
  - 리뷰 원문을 주는 공식 API는 없음
  - 크롤링은 소요 시간보다 차단이 병목임
  - 대안: 카카오 로컬 API(가게 목록) + 네이버 블로그 검색 API(후기 요약) → 가게별 평판·키워드 생성, 동대문구 음식점 전체를 하루 안에 처리 가능

**[시사점]**
- 결과를 가장 크게 흔드는 건 모델 기준값이 아니라 **데이터의 현실성**임 (배차 대기, 실제 이동시간, 실제 유입)
- 공공데이터는 '새로움'에는 강하고 '매력'에는 약함 → 매력은 설문과 리뷰 키워드로 보완해야 함
- 정답 라벨이 없는 한 성능 주장은 불가 → **설문이 가장 중요한 다음 데이터**임
